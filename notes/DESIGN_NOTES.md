# Recursive Privilege Architecture (RPA) — 设计要点提纯

> 本文档用于防止上下文压缩时丢失关键设计决策。保持简洁。

## 一、核心概念

**递归特权模型**：将特权等级从硬件固定转变为内存可配置，域数量由系统资源决定。

**相对视角**：
- 当前域看自己是 Domain 0
- 当前域看子域是 Domain 1, 2, 3, ...
- 当前域看父域是 Domain -1

## 二、核心原语（三个）

```
descend(block_addr)    进入子域，从控制块地址读取配置
escalate(service_type) 请求父域服务（包括异常上报、正常结束通知等）
return_to_child()       返回子域（父域调用）
exit()                  退出子域并释放资源
```

**escalate 的多种用途**：
- 服务请求：子域请求父域执行特权操作
- 异常上报：子域发生异常，请求父域处理
- 正常结束：子域执行完毕，上报父域进行资源回收

## 三、域编号约定

```
Domain 0    = 根域（最高特权，Root of Trust）
Domain 1    = 子域
Domain 2    = 孙域
Domain N+1  = Domain N 的子域
```

## 四、控制块结构（DomainBlock）

控制块大小：128 字节，对齐要求：32 字节边界

| 偏移 | 字段 | 设置者 | 说明 |
|------|------|--------|------|
| 0x00 | ctrlblock_size | 父域 | 控制块大小（必须为32的倍数）|
| 0x04 | exception_vector | 子域 | 异常处理入口 |
| 0x08 | reserved_08 | - | 保留 |
| 0x0C | interrupt_ctrl | 系统 | 中断控制器handle |
| 0x10 | ipa_regions | 父域 | IPA区域表地址（子域只读）|
| 0x14 | domain_id | 系统 | 域ID（系统分配）|
| 0x18 | pagetable | 子域 | 页表地址（子域可写）|
| 0x1C | child_block | 父域 | 子域控制块地址 |
| 0x20 | security_domain | 系统 | 安全域handle |
| 0x24 | access_id | 系统 | 访问ID（DMA用）|
| 0x28 | saved_sp | 硬件 | 保存的栈指针 |
| 0x2C | saved_lr | 硬件 | 保存的返回地址 |
| 0x30 | saved_psr | 硬件 | 保存的程序状态 |
| 0x40-0x83 | irq_saved_* | 硬件 | 中断现场保存区 |

## 五、关键设计决策

### A组：安全边界与硬件支撑

| 问题 | 决策 |
|------|------|
| A1. 内存访问隔离 | 通过页表隔离实现，父域不映射子域私有内存 |
| A2. 配置保护 | DomainBlock位于父域内存空间，子域无法直接修改 |
| A3. 根信任 | 外部认证建立，信任链逐域传递，非本文创新 |
| A4. 故障传播 | 区分"异常"（可处理）和"故障"（无法恢复）；故障自动escalate；系统级故障由根域处理 |

### B组：与现有机制的关系

| 问题 | 决策 |
|------|------|
| B1. 中断路由 | interrupt_ctrl通过handle传递；子域通过escalate请求注册中断；中断控制器通过软中断注入子域 |
| B2. 内存保护位 | 原语层分离语义（r/w/x），实现层映射具体架构，特殊保护用新域替代 |
| B3. 页表叠加 | 逐层翻译：VA → PT_{N+1} → IPA_N → PT_N → PA_{N-1} → ... → 物理地址 |
| B4. IPA边界检查 | 子域页表IPA必须在ipa_regions范围内，否则触发翻译错误 |

### C组：实现细节

| 问题 | 决策 |
|------|------|
| C1. 递归深度 | 理论无限，实际受控制块存储限制；栈式O(1)索引，链式O(depth)索引 |
| C2. 返回机制 | 父域通过child_block找到子域控制块，恢复上下文继续执行 |
| C3. 多核同步 | 各核独立工作；多核启动需父域授权；必须自上而下同步 |
| C4. 中断状态 | 自动管理：进入时禁用，退出时恢复；域间隔离：各域中断互不影响 |
| C5. 中断返回 | LR带IRQ_RETURN_FLAG标志位，bx lr自动检测并恢复上下文 |

### D组：论文相关

| 问题 | 决策 |
|------|------|
| D1. 形式化 | 结构化描述，不追求形式化证明 |
| D2. 评估 | Python解释器 + 三个案例（虚拟化、系统调用、try-catch） |
| D3. CHERI | 聚焦特权层级，内存权限留待后续研究 |
| D4. 定位 | 系统架构论文，参考设计，非顶会导向 |
| D5. 相关工作 | 差异显著则简要对比，重点说明统一抽象价值 |

## 六、页表叠加机制

```
Domain N+1 的 VA ──PT_{N+1}──► Domain N 的 PA
Domain N 的 PA   ──PT_N──────► Domain N-1 的 PA
...
Domain 0 的 PA   ──PT_0──────► 真实物理地址

INHERIT：共享页表，无叠加
    - 无页表切换
    - 无 TLB 刷新
    - descend/escalate 成本 ≈ 函数调用
    - 唯一开销：寄存器状态切换（调用约定决定保存者）

独立页表：叠加翻译，escalate成本 ≈ 传统trap
```

**INHERIT 模式低开销前提**：
- descend/escalate 不执行额外动作（如额外检查、状态同步）
- 模拟器实现中，INHERIT 模式直接跳过页表翻译步骤
- 无额外动作 = 近似零成本（仅寄存器切换）

## 七、异常与故障

```
异常 (Exception) = 突发事件
    ├── 故意的陷阱 (Trap)：页错误、系统调用、断点 → 可恢复
    └── 故障 (Fault)：总线无响应、内存耗尽 → 确定后由 fault_handler 处理

处理流程：
    异常发生 → exception_vector
        ├── 判断为可恢复 → 处理后返回子域继续
        └── 判断为故障 → 转交 fault_handler → 可能终止子域

关键点：
    - 异常发生时不知道是不是故障
    - 父域先接收异常，判断后再决定是否转交 fault_handler
    - 故障是"确定为不可恢复"的异常子集
```

## 八、故障传播

```
故障确定后：
  → 当前域停滞
  → 所有子域停滞
  → escalate 到父域
  → 父域故障中心处理
```

## 九、层级信息隔离

```
每层只关心直接上下级：
  - 父域不知道请求来自哪个孙域
  - 父域知道来自哪个子域（自己管理的）
  - 向上汇报时剥离子域信息
  - 不考虑越级汇报
```

## 十、原语精确定义

```python
# ═══════════════════════════════════════════════════════════════
# 递归特权架构 (RPA) 原语定义 v1.0
# ═══════════════════════════════════════════════════════════════

descend(params):
    """
    进入子域
    - 默认进入 sub[0]
    - params 传递给子域
    - 子域视角：自己是 Domain 0
    """

escalate(params):
    """
    请求父域服务
    - params 传递给父域
    - 父域通过向量接收
    - 用途：服务请求、异常上报、正常结束通知
    """

return_to_parent(result):
    """
    返回父域（子域正常完成时调用）
    - result 传递给父域
    - 父域从 descend 调用点继续执行
    - 与 escalate 的区别：
        - escalate：请求服务，处理后继续在子域执行
        - return_to_parent：结束执行，控制权永久返回父域
    """

# 多子域扩展（实现层定义）
descend_n(n, params):
    """
    进入 sub[n]
    - 由实现层根据需求扩展
    """
```

**典型流程**：
```
Try-catch 正常结束：
    子域执行完毕
    → escalate({type: "complete", result: ...})  // 通知父域，父域可回收资源
    → return_to_parent(result)                   // 控制权返回父域

Try-catch 异常：
    子域发生异常
    → escalate({type: "exception", info: ...})   // 上报异常
    → 父域处理（可能终止子域）
```

## 十一、核心价值主张

**统一抽象**：
- 虚拟化：自然支持嵌套
- 机密计算：父域可管理子域配置但不访问内容
- JIT沙箱：创建子域隔离执行
- Try-catch：子域实现，零开销异常处理

**一句话总结**：
> 共享即信任，信任省检查。
