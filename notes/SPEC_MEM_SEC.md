# NPA 设计规格 · 内存 + 安全子系统（lazy）

> 版本：v0.1 — 复盘稿  
> 依赖：`SPEC_NPA_CORE.md`（域 / DCB / lifecycle / I1–I20）  
> 范围：逻辑内存模型（无 cache）、安全域认证链、机密计算密钥归属。  
> 原则：宗旨为实现让路；发现漏洞先讨论再改（CORE §1 元原则）。

## 0. 分层与职责

> **范围：** 我们定 **架构要求**（功能、接口、信任与密钥归属）。验证算法、root trust 存哪、协议报文等 **交给实现**。

```text
安全子系统：  preset、root→bind 链、密钥归属     ← 规格要这些能力
内存（lazy）：翻译、ipa、机密读写语义           ← 规格要这些语义
DCB/域：      ptb/ipa/sec/id；父配约束，无密钥
```

| 子系统 | 管什么 | 不管什么 |
|--------|--------|----------|
| **内存（lazy）** | 逻辑地址：翻译、约束、机密读写是否成功 | cache/TLB/时序/带宽 |
| **安全** | 谁是安全域、根信任、密钥 | 具体页表格式、调度 |

## 1. Lazy 内存子系统（只做逻辑）

### 1.1 模型

- **无 cache / 无 TLB 失效语义**：每次 `load/store` 当即求值并检查。  
- **一次访问** =  
  1) 用当前域视图把 VA → PA（继承 / 叠加链，见 CORE §5）  
  2) `ipa` 权限表检查（形态 1/2 查 VA，形态 3 查 IPA）  
  3) **机密检查**（§3）  
  4) 才允许读写  

### 1.2 区域属性（逻辑表）

在权限 `R/W/X` 之上增加 **机密属性**（仍表驱动，不进 Spec 新字段）：

```text
Region { base, size, attr(R/W/X), owner_id, conf: none|enc }
```

| conf | 含义 |
|------|------|
| `none` | 明文，受 ipa/翻译约束即可 |
| `enc` | 机密区：**按密钥读写**；无钥访问不得得到明文 |

**owner_id**：逻辑归属（用于密钥查找与审计），不是 DCB 字段。

### 1.3 lazy 边界（明确不承诺）

| 不做 | 理由 |
|------|------|
| cache 一致性 | 属实现/平台 |
| 页填充、预取 | 与特权语义无关 |
| 物理攻击 / 总线嗅探 | CORE §8 已不承诺侧信道 |

## 2. 安全子系统

### 2.1 需求

> **用户/系统能把某个域指定为安全域**，且必须有 **从 root trust 到该域** 的验证路径。

### 2.2 角色

| 角色 | 职责 |
|------|------|
| **Root of Trust** | 启动/外部度量；持有或锚定根密钥材料 |
| **安全子系统** | 预设表、attest/bind、密钥生成与下发 |
| **父域** | 建 DCB、`descend`、配 `ipa`/`ptb`；**不**自动获得密钥或内容读权 |
| **安全域** | 绑定成功后的子域；可持有机密区 |

### 2.3 预设登记（对齐 CORE §8.1 / I16）

```text
preset:  id → { role, conf_policy, … }
bind(id):  id ∈ preset 且策略允许 → sec_handle（+ 可选密钥）
           否则拒绝
```

- **域 ID** 是认证主键（§2.3）；δ/树深度不能代替身份。  
- 「指定为安全域」= **登记命中 + bind 成功**，不是子自封、不是父随便写 `sec`。

### 2.4 验证路径（root → 安全域）

```text
外部度量 / 启动锚
    → Root Trust（度量可信、装载策略、写 preset）
        → 安全子系统（继承信任）
            → bind(absolute id) 
                → 该域成为安全域（sec 有效、可获密钥）
```

| 检查点 | 内容 |
|--------|------|
| 链完整性 | 每一级域的 `id`/度量符合 preset 或策略 |
| 绑定 | `id` 在 preset；失败不得 `sec`/密钥 |
| 运行时 | 机密区访问见 §3；父无钥 → 不得明文 |

**机密计算下父域不是信任根**：父可管理 **配置**（ipa/ptb/lifecycle），**不可**读内容、**不可**向安全子系统索取子密钥。

### 2.5 接口要求（规格）；算法与存放（实现）

规格只规定 **要有什么能力**（语义见上表）：`preset`、`bind`、`attest`、密钥设置、访问检查。  
**算法、root trust 载体、报文、固件布局 — 一律实现选择。**

## 3. 机密计算（依赖内存 + 安全）

### 3.1 密钥归属

| 项 | 归属 |
|----|------|
| 区域密钥 K | **安全子系统**生成/保管 |
| 写入内存控制器/引擎 | **安全子系统**（或 root 代管），**非父域** |
| 父域 | 只见 DCB、翻译表、访问 **成功/失败**；**无 K** |

### 3.2 访问语义（lazy）

```text
access(PA, viewer, conf=enc):
    if viewer 有权（owner / 安全组 / 获授权）:
        用 K 明文读写
    else:
        失败  或  仅密文（实现定；模型取失败更严）
```

**不变量：**

1. 父域即使持有 PA / 映射，也 **不能** 通过 DCB 或普通读指令得到子机密明文。  
2. 密钥不得写入 DCB Spec；最多 Impdef/安全子系统私有。  
3. 隔离失败（无钥读）必须失败，禁止静默返回明文。

#即 CORE「管理权 ≠ 内容访问权」的机密加强版。

## 3.5 优化层（后置）：cache 加速 page table hit

**前提：** lazy 语义（§1）是架构真相；cache/TLB **只加速，不得改可见结果**。

```text
软件可见:  lazy 检查（翻译链 + ipa + 机密）
              ▲
              │ 语义等价
硬件加速:  TLB / PT walk cache / 页表项 cache
```

| 机制 | 加速什么 | 约束 |
|------|----------|------|
| **TLB** | VA→PA（或 VA→父视图→…）命中 | 项必须含 **域 ID / 安全域** 标签，避免串域 |
| **PT entry cache** | 页表 walk 中间项 | 失效与 lifecycle/`ptb` 变更一致 |
| **ipa 允许表 cache** | 权限覆盖命中 | 与 §1.2 表同源；改表后可见性策略见下 |
| **机密区** | 密钥引擎吞吐 | **不**因 cache 泄漏明文给无钥访客 |

**等价性要求（实现验收）：**

1. **同一访问**：cache 命中与否，load/store 成功/失败/明文必须一致。  
2. **TLB 带域标签**：`id`（或安全域 ID）必须进 tag，切换域不得误用旧项。  
3. **`ptb`/lifecycle/reap**：重配或 TERM/FREE 后，旧翻译缓存必须不可见（flush 或带 generation）。  
4. **ipa 热更新**：若采用 CORE「descend 粘滞」，cache 不得比粘滞视图更宽。  
5. **机密**：cache line 加密或按域分区；父域命中路径不得读到子明文。

**性能故事（论文用）：** INHERIT / 共页表时 TLB 不刷则 ≈ call；独立 `ptb` 时 walk cache 降 miss；**绝对 cycle 仍须 gem5/硬件**，cache 只解释比值。

**明确不做（本阶段）：** 多级 cache 一致性协议、预取策略、替换算法——留给实现论文，不进逻辑 Spec。

## 4. 与 CORE / DCB 的接口

| 符号 | 本卷 |
|------|------|
| `ipa`/`ptb` | lazy 内存的翻译与约束 |
| `id` | bind / 密钥查找主键 |
| `sec` | bind 成功结果；可关联 conf_policy |
| lifecycle | 与安全无关；杀域后密钥应失效（reap/bind 撤销） |

**Spec 字段不增加**（P1）：机密/密钥在安全子系统与内存表，不在 10-word Spec 扩格。

## 4. 两类安全域（仅要点 + 测试）

- **普通安全域**：除 root trust 外隔离；root 可读内容。  
- **机密安全域**：含 root 在内不可被动读；仅 `ascend(x)` / 共享窗等 **显式暴露** 后可见。  
- **secure lib**：不单列类型；= 小/复用地址空间的 sec/csec，验码后短跑 `EXIT`。

**控制权 vs 可见性（定论）：**

| | 父域 / 高优先级打断 | 读内容 |
|--|---------------------|--------|
| 普通 sec | **可以**打断、调度、reap | root 可读；其它域否 |
| 机密 csec | **可以**打断、调度、reap | **否**（含 root），除非显式暴露 |

即：父域可经中断/抢占/EXIT 打断安全域执行；**机密域只对「内容」不可见**，不是不可管理。

### 4.1b 伪装上下文（csec 抢占 / 恢复）

父域要调度就需知道「停在哪了」，但 **不能** 看 csec 真身 Context。由安全子系统中介：

```text
csec 运行中
  │  高优先级中断 / preempt
  ▼
安全子系统: 真 Context 入安全侧保管
            对父只给「伪装 Context」（token / 空壳，无真 PC/寄存器）
  ▼
父域: 可挂 runqueue、再 descend(dcb) — 不解内容
  ▼
安全子系统: 校验 token → 还原真 Context → 进入真 csec
```

| 方向 | 父域看到 | 谁负责 |
|------|----------|--------|
| 抢占 / `ascend` | 伪装 Context + 可公开的 reason/x | 安全侧 **脱下** |
| 恢复 `descend` | 仍只递 DCB；不读壳内内容 | 安全侧 **穿上** |

**不变量：** 伪装不得还原真身（除非 root+授权审计策略）；父有壳 ≠ 有内容读权；token 与 lifecycle 绑定，TERM/reap 后失效。

普通 sec 若 root 可读，可直接真 Context；**csec 默认伪装**。

规则见 I25–I28；行为以 **测试 S8–S11 + isolation 矩阵** 为准。

## 5. 场景刺探清单

| # | 场景 | 期望 |
|---|------|------|
| S1 | 普通域非机密读 | 转换+ipa 通过即可 |
| S2 | 指定安全域：id 不在 preset | bind 失败，无 sec/密钥 |
| S3 | id 在 preset → bind | 成功；可建 enc 区 |
| S4 | 父读子 enc 区 | **失败**（无 K） |
| S5 | 子读自己的 enc 区 | **成功** |
| S6 | 越 ipa 窗口（含 enc） | 失败（翻译/约束） |
| S7 | 子 EXIT 后父 reap 再复用 | 新域旧密钥不得沿用 |
| S8 | 普通 sec：root 读 / 父读 | root 成功，父失败 |
| S9 | csec：root 读 / 本域读 | root 失败，本域成功 |
| S10 | csec 主动暴露（x 或共享窗） | 暴露后父可见；未暴露仍不可 |
| S11 | 小地址空间 sec/csec（secure lib 形态） | 验码后短跑 EXIT，密钥废止 |

## 6. 不变量（追加建议）

| ID | 内容 |
|----|------|
| **I21** | 内存子系统 lazy：无 cache 语义；每次访问立即检查翻译/ipa/机密。 |
| **I22** | 安全域 bind 必须经 root 信任链 + preset 校验绝对域 ID（强化 I16）。 |
| **I23** | 机密区密钥由安全子系统持有；**父域无钥不得读明文**。 |
| **I24** | 密钥不得进入 DCB Spec 字段。 |
| **I25** | `csec`：root trust 亦不得被动读明文；仅显式暴露后可见。 |
| **I26** | secure lib 形态 = 小/复用地址空间的 sec/csec：执行前须验码；EXIT/reap 后密钥废止（非新域类型）。 |
| **I27** | 父域可用中断/抢占打断安全域；**csec 仅内容不可见**，不禁止控制与生命周期管理。 |
| **I28** | csec 抢占时父域只得到 **伪装 Context**；恢复由安全子系统还原；伪装不得泄露真身。 |

## 7. 刻意不做

| 不做 | 理由 |
|------|------|
| cache/TLB 模型 | lazy，逻辑优先 |
| Spec 增加 `key_id` 字段 | 避免驾驶舱；走安全子系统 |
| 父域可配子密钥 | 违背机密计算目标 |
| 远程证明全栈 | 只保留「链到 bind」接口 |
