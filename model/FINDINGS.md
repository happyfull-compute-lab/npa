## 1. 必须讨论：地址视图三种形态（Spec 空档）

总卷 §5 只写了：

| 条件 | 旧语义 |
|------|--------|
| `ptb=0, ipa=0` | INHERIT |
| `ptb≠0` | 叠加翻译 + `ipa` 边界 |

**MCU 与 JIT 场景逼出第三形态**（否则无法表达）：

| 条件 | 新语义（建议） | 场景 |
|------|----------------|------|
| `ptb=0, ipa=0` | 纯继承：同父翻译 + 同父权限 | try-catch、trust 子域 |
| **`ptb=0, ipa≠0`** | **继承翻译 + `ipa` 作权限覆盖表** | MCU 沙箱、JIT 共页表 |
| `ptb≠0` | 子 VA→父视图地址，再链到 PA；`ipa` 约束父视图地址 | 用户/客户机 |

### 为何不是新字段

- 不增加 Spec 概念（P1）；只是 **`ipa` 在 `ptb=0` 时的解释**。  
- 与口号一致：共享页表即信任翻译，**不信任权限**时收紧 `ipa`。

### 约束表查在哪个地址（不对称，需知情）

| 形态 | `ipa` 检查的对象 | 理由 |
|------|------------------|------|
| `ptb=0, ipa≠0` | **VA**（与父同名） | “同一地址空间、改权限” |
| `ptb≠0, ipa≠0` | **父视图地址（IPA）** | 父域分配给子的窗口 |

JIT 断言实测：能 X 代码段、W 数据段、不能 W 用户栈、不能 W 代码段 —— 符合“共页表、收权限”。

## 2. 已在模型中踩到并修掉的实现坑（非 Spec 争点）

| 坑 | 含义 |
|----|------|
| 堆叠只做单层 | 必须 `parent_view` 链到 PA；否则 3 层场景假绿 |
| 表终止项 `(0,0,0)` 与 VA0 映射冲突 | 全零终止或 attr=0/显式长度；**不能** `base=0,size=0` 一刀切除非 attr 也为 0 |
| `Access` 用 `IntFlag` | 便于表里存整数 attr |
| C1 换子域 | 软件 `rebind_child` 后 `descend`，单 `child` 字段够用 |

## 3. 场景结论（控制流）

| 场景 | 层数 | 结果 |
|------|------|------|
| MCU monitor/app | 2 | 继承 + 权限表隔离固件数据；SERVICE 往返；C1 换 app |
| monitor/kernel/user | 3 | 链式翻译到物理；IPA 窗口拒绝越权；双级 ascend/descend |
| + hyp | 4 | hvc 等同 ascend(SERVICE)；无新原语 |
| + JIT | 5 | `ptb=0,ipa≠0`；权限覆盖；resume |

**EL 仅注释对照，模型无 EL/Ring 概念** — 符合 P4/P5。
